Privacy Policy

This policy explains how the independent AsterByte project processes data when people install or use the AsterByte Discord application. AsterByte is currently a limited private beta operated from India.

Data we process

  • Discord identifiers for users, servers, channels, roles, interactions, and messages needed to route and authorize requests.
  • Prompts submitted through commands, mentions, replies, or the configured prefix.
  • Recent channel messages only when a user invokes a channel summary or channel-input workflow, or a server manager enables a scheduled digest after AsterByte posts a visible notice in that channel.
  • Optional conversation memory, reminder text, reusable workflow instructions, private-beta feedback, server settings, quota records, entitlement state, and confirmed-action audit records.
  • Operational metadata such as provider/model, timestamps, success status, and error category. Stateless prompt text is not written to application logs or the database by default.
  • Optional dedicated Groq or OpenRouter API keys submitted only through the private connection form, stored with authenticated encryption, plus provider/connection timestamps. The connection belongs to your Discord user across servers. Credentials are excluded from data exports.
  • Transient poll/trivia votes, game/channel IDs, and expiry times held in memory for up to ten minutes (or until replacement/restart). Results do not list voters; AsterByte does not persist a game history.

Why we process it

We process this information to provide requested AI responses and automations, enforce Discord permissions and quotas, prevent abuse and duplicate execution, deliver reminders, maintain opt-in memory, support users, and improve reliability and security.

AI providers and subprocessors

Prompt content needed for a response is sent to the AI provider configured for the request: Groq or OpenRouter. Interactive requests use a connected personal key when present, without silent fallback; otherwise the limited shared beta account is used. Scheduled digests currently use the shared beta provider, not personal keys. A connection is validated through the selected provider's authenticated account/models API. For action-like prompts, accessible server channel and role names/IDs may be sent to propose valid targets. Providers process data under their own terms and privacy policies; Discord processes data required for its platform.

Storage and retention

  • Stateless /ask prompt and completion text is not stored by AsterByte after the response.
  • Opt-in chat memory retains only the configured recent-message window until the user resets or deletes it. Saying “remember this conversation” enables use of this context for 24 hours in that server/channel/user scope; after that, context use stops but saved messages remain until reset or deletion. Channel replies are visible to channel readers, even with user-scoped memory.
  • Pending reminders and workflow definitions remain until executed, cancelled, or deleted. Completed reminder records are deleted after approximately 30 days.
  • Usage metadata and completed action audit records are deleted after approximately 90 days.
  • Minimal daily quota counters (UTC day, server/user scope and count; no prompt text) survive content deletion to prevent quota-reset abuse. Only current/previous UTC-day counters remain after hourly cleanup while online; cleanup also runs at startup. The operator-wide aggregate attempt counter has no user identifier. Your daily counters are included in exports.
  • Scheduled digest definitions expire after 30 days unless a manager renews them. AsterByte does not persist the raw channel messages processed for a digest.
  • Encrypted personal keys remain until replaced, disconnected, or deleted. /connect disconnect removes the live connection across servers, not provider-side copies or recovery backups. Revoking the dedicated key in the provider dashboard invalidates it at its source. The local connection form is currently operator-only; public HTTPS onboarding is not deployed.
  • The local private beta uses filesystem-restricted SQLite recovery snapshots. These can retain deleted data and currently require manual expiration; they are not automatically erased by /data delete. Contact support for deletion from recovery snapshots. Backups are not used for AI responses.

Choices and deletion

Use /privacy for an in-product disclosure and /data status, /data export, or /data delete to inspect, export, or delete user-scoped records for a server. The export includes the stored record contents, not only counts. Say “forget this conversation” to clear your saved window in the current channel. Server managers can request deletion of server configuration and shared workflows through support; removing the app alone does not erase its database records. Some minimal security records may be retained where reasonably necessary to prevent abuse or comply with law.

Security

AsterByte applies tenant scoping, parameterized storage, strict schemas, quotas, timeouts, requester-bound confirmations, repeated permission checks, action allowlists, audit records, restricted mentions, and authenticated encryption for saved provider keys. The private form uses short-lived single-use links, same-origin checks, and no-store responses. Encryption does not protect against complete compromise of the bot host and master key. No service can guarantee absolute security. Never put passwords, tokens, API keys, payment details, or sensitive personal data in Discord messages or prompts; dedicated provider keys belong only in the private connection form.

Children

AsterByte is not directed to children below the minimum age required to use Discord in their country. If you believe a child has provided personal data contrary to applicable rules, contact support.

International processing and changes

Discord and AI providers may process information in other countries. We may update this policy as the beta changes. Material changes will update the effective date and, where practical, be announced through the app or support channel.

Contact

Open a privacy ticket in the AsterByte support tracker. Do not post secrets or private message content in a public issue; request a private contact route if necessary.
